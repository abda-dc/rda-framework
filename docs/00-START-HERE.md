# RDA — Repository Due-diligence & Audit framework

**What you asked for:** a production-grade reusable skill framework for repository inspection and technical due
diligence, portable across ten agent environments, researched before built.

**What was built:** 38 skills in six layers, a machine-enforced evidence contract, a coverage model, an
adversarial verification gate, seven execution profiles, adapters for every target environment, and six working
scripts — validated end to end.

## The five things worth knowing before anything else

**1. The gap is not coverage of topics — it is coverage of *evidence*.** Across roughly sixty comparable
assets surveyed, none emits a numeric statement of what fraction of the repository it inspected. The field has
plenty of code reviewers and no auditors.

**2. Two of your ten target environments have changed status.** GitHub Copilot **Workspace was retired**
(sunset 30 May 2025) — the framework targets Copilot cloud agent, code review and VS Code agent mode instead.
**Windsurf is now documented under Devin Desktop**, with `.devin/` preferred and `.windsurf/` as fallback. Roo
Code's extension has been archived. All three are still covered, because adapters are generated from one
canonical pack rather than hand-maintained.

**3. Portability turned out to be nearly free.** `.agents/skills/` is a shared discovery path honoured by
Codex, Cursor, Gemini CLI, Copilot/VS Code and Devin Desktop; Claude Code reads only `.claude/skills/` **but
follows symlinks**. One tree plus one symlink covers every skills-capable environment. What is *not* portable —
Cursor `.mdc`, Copilot `.instructions.md`, Devin/Antigravity `trigger:` rules, Roo modes, Aider conventions,
Gemini TOML — is generated by a script.

**4. The architecture is dictated by evidence, not preference.** Repo-scale analysis is a retrieval-and-
verification problem: effective context collapses well before advertised limits, accuracy degrades with input
length at constant difficulty, and audit questions have low lexical overlap with the code that answers them.
Unaided LLM vulnerability detection collapses on leakage-controlled benchmarks and flips verdicts when
identifiers are renamed, while tool-grounded adjudication performs materially better. Hence: deterministic tools
over 100% of the corpus, model reading over risk-weighted strata, and adjudication rather than invention.

**5. The governance is executable.** `validate_findings.py` rejects a finding that claims SOC 2 compliance,
asserts dead code as fact, carries a numeric self-confidence, quotes a person-day estimate, or claims C3 without
a tool result — and `verify_citations.py` re-reads every quote at the pinned commit and quarantines what does
not resolve. Both are tested in both directions: `templates/example-findings-invalid.json` is a deliberately
malformed fixture that trips **44 violations across 28 distinct codes**, while the conforming example must
trip none. `scripts/selftest.py` asserts both, so a gate that silently stopped enforcing would fail CI.

## Try it in ninety seconds

```bash
python3 scripts/selftest.py                              # every gate, both directions (70/70 codes)

python3 scripts/validate_pack.py skills --budgets        # conformance, profile closure, metadata budgets
bash    scripts/rda_census.sh /path/to/repo ./rda-out    # deterministic denominators
python3 scripts/validate_findings.py templates/example-findings.json \
                                     --coverage templates/example-coverage.json
python3 scripts/generate_adapters.py --check             # adapters match their source of truth
python3 scripts/verify_citations.py templates/example-findings.json --repo /path/to/repo
scripts/install.sh --profile P4 --target /path/to/repo   # M&A profile, all environments
```

`verify_citations.py` is expected to fail on the shipped example: its commit SHAs are synthetic, and the
verifier is built to fail closed rather than wave through a citation it cannot re-read. Point it at a real
findings file and a real checkout to see it pass.

## What this framework will not do

Recommend deleting code without runtime evidence · price anything without billing evidence · declare compliance ·
evaluate individuals · modify the code under audit · or issue a verdict on coverage too thin to support one.
`INSUFFICIENT_BASIS` is a first-class outcome, not a failure.
